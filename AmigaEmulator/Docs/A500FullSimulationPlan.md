# A500 full simulation plan

Goal: complete the Amiga 500 hardware path without renderer shortcuts. The immediate milestone remains the real Kickstart 1.3 insert-disk screen generated by ROM, graphics.library, Copper, bitplane DMA, sprites, and Denise.

Priority key:

- `P0`: blocks or can directly block the real Kickstart boot display.
- `P1`: required for a usable emulator or likely to affect boot correctness.
- `P2`: correctness/product maturity after the boot display path is stable.
- `P3`: later polish, UI, distribution, or non-boot features.

## Current P0 diagnosis

Kickstart reaches the real graphics.library/Copper/bitplane display setup, but the generated bitmap is still wrong. The current failing state is:

- `--run-until-pc FE861A 300000000 1` reaches the ROM bitplane-DMA enable instruction with `OverlayAtZero=False`.
- The Copper list at `$010450` is real and stable: palette, DIW/DDF, BPL pointers, and two-plane enable are all present.
- At 90M cycles: `BPLCON0=$2302`, `BPL1PT=$0000A572`, `BPL2PT=$0000C4B2`, `COLOR00=$0FFF`, `COLOR01=$0000`, `COLOR02=$077C`, `COLOR03=$0BBB`.
- Plane 1 contains large `$FFFF` runs beginning at `$A572`, while plane 2 contains `$0000`; the final palette renders this as the wrong black field.
- Targeted blit traces show real graphics.library screen-copy blits from `$0104B8` into `$A572/$C4B2`.
- `$0104B8` is produced by earlier vector/fill blits. Around 13.25M cycles, `CON0=$03CA`, `CON1=$0000`, `size=$0054`, `C/D=$0104B8` writes full-width `$FFFF` spans.

The fix must be upstream of Denise helper rendering and focus on Blitter line/fill exactness, especially the graphics.library vector outline/flood-fill sequence.

## Execution order

1. Done: add a deterministic P0 bootscreen assertion command: View/CprList fields, COP1LC/COP2LC, BPL pointers, core state.
2. Done: keep 68000 address registers internally 32-bit while masking only external A500 bus addresses to 24-bit.
3. Done first slice: make Blitter asynchronous enough for Busy/IRQ/timing correctness and attach Blitter DMA slots to Agnus.
4. Done first slice: fix remaining `CustomRegisterMap` read/write side effects and readbacks needed by Kickstart.
5. Done first runtime slice: derive PAL frontend timing from the A500 clock and default normal window execution to the fast non-tracing profile.
6. In progress: replace heuristic DMA scheduling with a complete PAL slot table for Copper/Bitplane/Blitter/Sprite priority.
7. Next: complete Paula disk DMA + ADF MFM stream for actual ADF boot.

## Latest implementation notes

- `Program.cs` now has `--assert-kickstart-screen-path [cycles]`.
- `M68kCpu.cs` no longer truncates A registers to 24-bit internally; `M68kSelfTest.cs` covers full-width A registers with 24-bit bus masking.
- `Blitter.cs` now starts work at `BLTSIZE` but completes it word-by-word on Blitter DMA slots.
- `DmaScheduler.cs` now emits `DmaOwner.Blitter` only when Blitter DMA is enabled and the Blitter is busy.
- `DmaScheduler.cs` now shares the same `BitplaneUnit` instance used by Agnus for real bitplane fetches, so scheduler fetch-slot decisions and fetch state are no longer split across two units.
- `Agnus.cs` now ticks the Blitter on Blitter-owned DMA slots.
- `CustomRegisterMap.cs` now masks `DMACON` to writable DMA bits and handles byte writes to set/clear registers without merging in readback state.
- `Blitter.cs` now starts only on `BLTSIZE` word writes or low-byte writes.
- `Copper.cs` now executes Copper-origin `COPJMPx` directly instead of bouncing through the CPU register event path.
- `M68kCpu.cs` now vectors internal invalid-operation fallbacks through vector 4 and validates more illegal effective-address forms before operand side effects.
- `Program.cs` now has `--diagnose-kickstart-display [cycles] [--model a500|slow512]` and `--dump-words <address> <words> [cycles]` for focused ROM/list diagnostics.
- `M68kCpu.cs` now validates immediate ALU/CMPI, `OR Dn,<ea>`, `CLR`, `TST`, `NEGX`, `NEG`, and `NOT` against 68000 data-alterable/memory-alterable EA rules.
- `FDE600`/`FDB718` tracing confirms the missing `Screen+$3C` list head is earlier than `MrgCop/LoadView`; only zero writes to `$49C0..$49C3` are observed.
- `Program.cs` now has `--trace-blits cycles maxBlits startCycle [filterStart filterEnd]` for focused blitter-start diagnostics.
- `Blitter.cs` now preserves preloaded source data registers when the corresponding source DMA channel is disabled; `BlitterSelfTest.cs` covers the disabled-A mask latch regression.
- The real Kickstart 1.3 insert-disk screen now renders through ROM, graphics.library, Copper, Blitter, Chip RAM bitplanes, and Denise output.
- `AmigaModel.cs` now exposes PAL chip clock and frame rate derived from the A500 CPU clock.
- `M68kCpu.cs` now uses a centralized per-instruction cycle budget converted into chip-cycle slots instead of a fixed three-chipcycle delay after every instruction.
- `AmigaWindow.cs` now starts from the persisted accuracy profile, migrates old settings to `FAST`, exposes `ACCURACY` in Settings/Machine, and shows host emulation speed in the debug overlay.
- Current verified blocker for a complete A500: actual disk boot still needs Paula disk DMA, MFM track decoding, CIA/keyboard/input polish, sprite priority/collision accuracy, and full save-state serialization.
